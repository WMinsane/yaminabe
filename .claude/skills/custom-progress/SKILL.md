# 進捗確認

基準日: $ARGUMENTS（省略時は今日の日付を使用）

## 1. 計画線の読み込み

`.docs/schedule.md` を読み込み、以下を把握する:
- 週次スケジュール（どの週にどのフェーズが割り当てられているか）
- フェーズ別タスク分解（各タスクの完了状態 `[x]` / `[ ]`）
- 基準日が属する週（W1〜W6）と、その週で完了すべきフェーズ・タスク

## 2. 実態の確認

各ドキュメント・成果物の実際の状態を確認する:
- `.docs/` 配下のファイル存在チェック（Glob）
- 各ドキュメントの内容量・完成度の概観（Read冒頭）
- schedule.md のチェックボックス状態

## 3. 差分分析

タスク単位で以下を判定する:

| 判定 | 条件 |
|------|------|
| **前倒し** | 計画線より先の週に割り当てられたタスクが完了済み |
| **予定通り** | 当該週に割り当てられたタスクが完了済み |
| **遅れ** | 当該週までに完了すべきタスクが未完了 |
| **未到達** | 計画線上まだ着手不要（評価対象外） |

## 4. 出力フォーマット

```markdown
# 進捗レポート

**基準日**: {YYYY-MM-DD}（{W?} {曜日}）
**当該週の計画**: {フェーズ名と目標}

## 計画線との差分

### 遅れ（計画線より後ろ）
| フェーズ | タスク | 計画完了週 | 状態 | 遅れ幅 |
|---------|--------|-----------|------|--------|
（なければ「なし」）

### 前倒し（計画線より前）
| フェーズ | タスク | 計画完了週 | 状態 | 前倒し幅 |
|---------|--------|-----------|------|---------|
（なければ「なし」）

### 予定通り
| フェーズ | タスク | 状態 |
|---------|--------|------|

## 総合評価
- **遅れタスク数**: {N}件（推定遅延: {X}日）
- **前倒しタスク数**: {N}件（推定前倒し: {X}日）
- **純差分**: {+X日 or -X日 or ±0}
- **MVP目標（2026-04-30）への影響**: {影響なし / 要注意 / 危険}
- **コメント**: {1〜2文で現状の総括}

## 推奨アクション
- {遅れを取り戻すための具体的アクション、または前倒しを活かす提案}
```

## 5. 遅延推定の基準

- 1フェーズ = 約1週間（10時間）を基準とする
- タスクの粒度に応じて按分する（例: フェーズ内に4タスクあれば1タスク ≒ 2.5時間 ≒ 1.75日）
- 前倒しと遅れは相殺して純差分を算出する

## ルール
- schedule.md のチェックボックス状態が実態と乖離していれば、その旨を報告する（勝手に更新しない）
- 計画線の変更提案は行わない。差分の報告に徹する
