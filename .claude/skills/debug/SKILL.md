# バグ修正手順

対象: $ARGUMENTS

## フェーズ1: 原因調査
- バグの再現手順を確認する
- 関連するコード・ログ・エラーメッセージを調査する
- 原因の仮説を1つ立てる
- 仮説をユーザーに提示し、承認を得る

**禁止**: 原因調査なしに修正を試みない。

## フェーズ2: 最小変更で検証
- 仮説に基づき、最小限の変更を1つだけ行う
- 検証コマンドを実行し、結果を提示する
- 修正が成功した場合 → フェーズ3へ
- 修正が失敗した場合 → 失敗回数を記録し、フェーズ1に戻る

## フェーズ3: セルフレビュー
修正内容を以下の観点で確認する。問題がなければスキップしてフェーズ4へ進む。

- **PJルール遵守**: CLAUDE.md・CONVENTIONS.mdのルールに違反していないか
- **冗長処理の有無**: 不要な処理・重複コードが含まれていないか
- **根本原因の解決**: 症状への対症療法ではなく、根本原因に対する修正になっているか
- **回避策に逃げていないか**: try-catch握りつぶし、フラグによるスキップ等で問題を隠していないか

問題がある場合はフェーズ2に戻る。

## フェーズ4: 修正確認
- 関連テストがすべて通ることを確認する
- 修正内容のサマリを提示する

## エスカレーション条件
同一バグに対して**3回修正を試みて失敗**した場合:
- 症状への対症療法を中止する
- 設計自体に問題がある可能性をユーザーに報告する
- 設計見直しの選択肢を提示する
