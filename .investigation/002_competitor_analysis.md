- **起票日**: 2026-04-11
- **Status**: Open
- **目的**: Yaminabeのポジショニング明確化。競合モデルの分類と、採用すべきアーキテクチャパターンの選定

---

## 競合サービス分類

### モデル A: SmartNews型（メディア提携型）

| 項目 | 内容 |
|------|------|
| 代表サービス | SmartNews, Gunosy, グノシー |
| 構造 | メディアと正式提携し、記事本文をアプリ内に取り込んで表示 |
| 収益モデル | アプリ内広告（本文表示による滞在時間確保） |
| 著作権 | 提携契約で許諾済み |
| 参入障壁 | **極めて高い** — メディア各社との個別契約が必要。法務・営業リソースが不可欠 |
| スタートアップ適性 | **❌ 非現実的** — 契約交渉にかかるコスト・時間がMVPフェーズと相容れない |

### モデル B: NewsPicks型（URL収集＋付加価値型） — **Yaminabe採用モデル**

| 項目 | 内容 |
|------|------|
| 代表サービス | NewsPicks, はてなブックマーク |
| 構造 | 外部記事のURLを収集し、コメント・要約・タグ等の付加情報を添えて提示。本文閲覧は元サイトへ遷移 |
| 収益モデル | フリーミアム（付加機能課金）、一部オリジナル記事 |
| 著作権 | **リスク低** — 記事本文を複製しないため、リンク＋メタ情報の利用にとどまる |
| 参入障壁 | 低〜中。RSS/APIで技術的に実現可能 |
| スタートアップ適性 | **✅ 現実的** — メディア提携不要。公開RSS/APIのみで構築可能 |

### モデル C: はてブ型（ソーシャルブックマーク型）

| 項目 | 内容 |
|------|------|
| 代表サービス | はてなブックマーク, Pocket |
| 構造 | ユーザー自身がURLを保存・共有。集合知で人気記事が浮上 |
| 特徴 | コンテンツ収集をユーザーに依存。運営側のキュレーション介入は限定的 |
| Yaminabeとの差異 | Yaminabeは運営側がコンテンツを自動収集・分類・レコメンドする点で異なる |

## Yaminabeの採用モデルと差別化

### 採用: NewsPicks型 + AI自動要約

```
[RSS/API] → [コンテンツ収集] → [AI分類・要約生成] → [パーソナライズ配信] → [元サイトへ遷移]
```

| 要素 | NewsPicks | Yaminabe |
|------|-----------|----------|
| コメント | 人手（著名人・ユーザー） | なし（MVP） |
| 要約 | 編集部 or なし | **AI自動生成**（Gemini） |
| カテゴリ分類 | 編集部 | **AI自動分類** |
| レコメンド | パーソナライズ | パーソナライズ＋**意図的ランダム性** |
| オリジナル記事 | あり（有料） | なし |
| 本文表示 | 一部アプリ内表示 | **常に元サイトへ遷移**（著作権リスク回避） |

### SmartNews型を採用しない理由

1. **契約コスト**: メディア各社との個別提携交渉が必要。1人開発では非現実的
2. **法務リスク**: 記事本文の複製・再配信には明示的な許諾が必要
3. **時間**: MVP段階で営業活動に時間を割くのは本末転倒

### NewsPicks型が適する理由

1. **著作権**: URLとメタ情報（タイトル・OGP画像・概要）の利用はリンクの範囲内
2. **実装**: 公開RSS/APIからの収集で技術的に完結。既にバッチ実装済み
3. **差別化余地**: AI要約・自動分類で「ただのリンク集」を超えられる
4. **スケーラビリティ**: コンテンツソース追加がRSS URL追加のみで可能

## AI要約による差別化

### 「ただのリンク集」を超える要素

| 機能 | 効果 |
|------|------|
| AI要約（1〜2文） | 記事を開く前に内容を把握でき、タップ判断の精度が上がる |
| AI自動カテゴリ分類 | 手動タグ付け不要。ソース横断で統一的な分類が可能 |
| おまかせレベル | エコーチェンバー回避を仕組みとして提供（競合にない独自機能） |
| 視野可視化ダッシュボード | 読了傾向の偏りを可視化し、行動変容を促す |

### 実装状況

- AI自動分類: **実装済み**（`batch/autotag.py` — Gemini 2.5 Flash-Lite）
- AI要約生成: **未実装**（分類と同じパイプラインで追加可能）

## 設計への示唆

| 領域 | 示唆 | 優先度 |
|------|------|--------|
| コンテンツ表示 | 記事本文は表示しない。タイトル＋メタ情報のみ。タップで元サイトへ遷移 | MVP必須 |
| バッチ処理 | 収集 → 分類の2段パイプライン（現行通り） | MVP必須 |
| 利用規約 | 「本サービスは外部記事へのリンクを提供するものであり、記事本文の複製・再配信は行いません」の明記 | リリース前 |
| AI要約生成 | `ai_summary`カラム追加＋要約バッチ。差別化要素だがサービス立ち上げ後に検討 | **保留** |
| 将来拡張 | ユーザーコメント機能追加時もNewsPicks型の延長線上で設計可能 | 将来 |
