# 記事レベリング（ドメイン別難易度）+ 配信モードUI改善

- **Status**: Open
- **Priority**: High
- **起票日**: 2026-05-23
- **更新日**: 2026-05-24
- **種別**: 仕様検討 → 設計確定（一部）

## 課題

1. 記事の難易度・認知負荷がユーザーに伝わらない。同じフィードに初心者向け記事と専門的な論考が混在
2. 設定画面の「配信モード」（5ボタン: バランス/発見/集中/トレンド/ランダム）が直感的でない

## 確定方針

### 配信モードのスライダー化

現在の5ボタンを廃止し、スライダー（1-5）に変更:

```
[さくっと読む] ──────●────── [じっくり読む]
     1    2    3    4    5
```

- スコアリング重み調整ではなく、ドメイン難易度によるフィルタ方式
- おまかせレベルのスライダーはそのまま残す（2本のスライダー構成）

### フィルタ方式

| スライダー | 表示対象 |
|-----------|---------|
| 1 さくっと | level 1のみ |
| 2 やや手軽 | level 1-2 |
| 3 バランス | level 1-3（全部） |
| 4 やや深め | level 2-3 |
| 5 じっくり | level 3のみ |

### ドメイン難易度（3段階）

| レベル | 基準 |
|--------|------|
| 1 (手軽) | 前提知識不要、軽く読める |
| 2 (標準) | 基礎的な技術知識が必要 |
| 3 (専門) | 業界知識・実務経験が前提 |

## 実装手順

1. **ドメイン整理（先行）**: 記事URLからドメイン抽出 → 不要ドメインをban → 新ソース追加検討
2. **難易度設定**: 残ったドメインにユーザーがレベル付与
3. **DB変更**: `feed_source`に`level`カラム追加（default 2）
4. **配信モードUI**: 5ボタン → スライダー化
5. **フィード取得**: スライダー値に応じたドメインレベルフィルタ適用

## DB設計

- `feed_source.level` INT DEFAULT 2（ソース単位で管理）
- `user_setting.delivery_mode` → `delivery_level` INT DEFAULT 3 に置換（将来マイグレーション）

## 関連

- `feed_source`テーブル: ソース管理の既存テーブル
- `domain_banlist`テーブル: ドメイン単位の管理パターンが参考になる
- GIGAZINEは除外候補（テクノロジー系に偏りすぎ）
- ナゾロジー、ITmedia/@IT系を新ソース候補として検討中
